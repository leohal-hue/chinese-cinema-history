# 中国电影史资料库

一个便于查询、核对、补充与共同维护的中国电影史资料项目。起步资料是用户提供的三份《中国无声电影剧本》影片信息 Excel，合计 420 条原始影片记录。范围仅代表当前来源，不是中国电影史完整片目。

## 现在开始

- 在线资料库：https://leohal-hue.github.io/chinese-cinema-history/
- 独立协作仓库：https://github.com/leohal-hue/chinese-cinema-history

双击 `docs/index.html` 即可试用，不需要安装软件。可按影片、影人名称候选、公司名称候选和核对事项查询，查看原始文字、来源位置和局部关系图。下载的纠错模板需填写后交给维护者，目前不会自动提交。

**当前版本已获用户确认，可继续整理。** 后续发现的疑点单独记录在 `assistant_notes` 栏和 `REVIEW_NOTES.md`，供用户确认，保留原表文字。来源书目、版本与页码可持续补全；现有逐条核对状态继续反映文献核实进度。

## 资料与文件

| 文件 | 用途 |
| --- | --- |
| `sources/*.xlsx` | 原表副本，保留原样；默认本机保存，公开上传需另行确认 |
| `sources/original_records.json` | 原始文字与行号快照；默认本机保存，公开上传需另行确认 |
| `data/films.csv` | 正式维护的影片条目，一条原始记录暂对应一个条目 |
| `REVIEW_NOTES.md` | 后续发现的具体疑点汇总，供用户确认 |
| `data/people.csv` | 人物名称候选，尚未完成身份消歧 |
| `data/companies.csv` | 机构名称候选，尚未完成异名或沿革核实 |
| `data/relations.csv` | 指向影片的职务或出品关系，每条保留原列位置与独立核对状态 |
| `data/sources.csv` | 来源文件、SHA-256、待补书目信息 |
| `data/review_queue.csv` | 待核对事项及处理说明 |
| `docs/` | 生成数据与展示网页，可用于 GitHub Pages |

`data/` 是维护入口。`docs/data.js` 与 `docs/catalog.json` 由正式数据生成，不要直接修改。原始快照保留不变，正式条目可以修订。不要同时维护多份 Excel 和 CSV 作为不同的正式版本。

## 一次核对怎样完成

1. 在 `data/sources.csv` 补全书目与版本。在影片或关系的 `source_page` 栏补充文献页码。原表行号不等于文献页码。
2. 核对影片条目与每条关系。只确认导演时，可以将相应关系改成“已核对”，影片总体状态仍保留“待核对”。
3. 修订展示字段，保持 `id` 不变。不同来源的冲突不能直接覆盖消失，先在核对清单保留原说法、出处与采用理由，并标记“有争议”。更细的逐字段多来源证据表列入下一阶段。
4. 在核对清单的 `resolution` 记录依据与处理结果。其状态独立，不会自动改变影片或关系状态。
5. 运行下面的生成检查命令，确认网页显示正确，再提交给维护者审核。

```sh
python3 scripts/build.py
```

该命令只使用 Python 标准库，检查编号重复、关联是否存在、来源与核对状态，再生成网站数据。它不验证史实。

## 自动提取的边界

- 片名保留原文，星号、别名、分集与续作均未自动清理或合并。
- 主演与角色不自动拆分。多人姓名、异常长度或明显分隔符进入核对清单。
- 仅 2—4 个连续汉字的主创字符串提为名称候选；这仍可能包含短姓名连写，须人工核查。相同字面姓名不等于同一个人。
- 不含空格、数字或明显分隔符的公司栏提为机构名称候选，不合并公司异名。
- 关系保留“编导／导演（原表）”等原始含义。不同职务不推导为雇佣、私人交往等关系。
- 年份保留原栏值，不从混入公司栏的年份推定，也不自行认定是摄制年或公映年。
- 缺失值是尚未录入或来源未载，含义需要核对。

初始导入结果：420 条影片记录、257 个人名候选、77 个机构名称候选、1,221 条关系、907 条核对事项。以上是机械提取数量，不是经过考证的实体总数。

## GitHub 协作与发布

本项目已发布到 `leohal-hue/chinese-cinema-history` 独立仓库，与上海影史地图使用不同仓库。网站通过 `main` 分支的 `docs/` 目录发布。

1. 确认首轮样本和公开内容，选定代码、数据、图片等各自适用的许可。本起步版未替项目指定开放许可，公开可查看不自动代表可任意再利用。
2. 创建 GitHub 仓库，上传项目。贡献者修改 `data/` 并运行生成命令，通过 Pull Request 提交。普通读者使用预置 Issue 表单提交依据。
3. 当前发布设置为 Settings → Pages → Deploy from a branch → `main` → `/docs`。提交生成后的网页数据会自动更新网站。
4. 后续每次核对与补充都通过审核提交，重新生成展示数据。自动检查工作流会验证 CSV，并核对生成数据是否同步。
5. 网页已提供 GitHub 仓库与纠错入口，资料修订由维护者审核合入。

无需运行一次性导入脚本来更新网站。`scripts/import_initial.py` 用于初始建库，发现正式数据存在时会拒绝重导，以免覆盖人工修订。以后新增来源应追加新编号并保留出处，不按现有排序重新编号。

下一步见 `START_HERE.md`；字段定义见 `DATA_DICTIONARY.md`。
